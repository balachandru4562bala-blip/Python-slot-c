--- Task 1.1: Diagnostic Analysis ---
1. Hard-coded absolute path: Script fails on any machine other than original author's PC.
2. Unclosed file handle: If an error occurs, the file descriptor remains open in the OS table.
3. Memory exhaustion: f.read() loads the entire file into RAM at once, crashing on large files.
4. Bare except: pass: Masks critical syntax and logic bugs and silently drops valid students with decimal amounts.
5. int() on currency: Hostel mess bills frequently include paise (e.g. 2450.50). int('2450.50') raises ValueError, silently dropping student Bhavana!
6. Repeated string concatenation (+): Incurs O(n^2) character copying overhead.
7. No audit log: Rejected student bills vanish with zero administrative traceability.

Design Defense (Task 1.3):
For a 50,000-line file (~3 MB to 50 MB), the repaired version consumes strictly O(1) memory by streaming lines through a generator buffer rather than buffering millions of characters. Context managers ensure deterministic file handle release even upon catastrophic I/O aborts. Specific exceptions capture malformed records into an administrative audit log, guaranteeing zero financial data loss and paisa-accurate ledger balancing.

--- Import Semantics Explained ---
1. `import attendance.stats`:
   Loads submodule 'stats' inside 'attendance' package into sys.modules.
   Must be called via full qualified name: `attendance.stats.calculate_stats()`.
2. `from attendance import stats`:
   Binds the identifier `stats` into local namespace; called as `stats.calculate_stats()`.
3. `from attendance.stats import percentage`:
   Binds ONLY the specific function `percentage` directly into current namespace.
